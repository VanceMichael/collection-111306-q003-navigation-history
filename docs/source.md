# 本地资料源约定

按钮通过真实 `history.pushState` 改路由；同一地址也可创建新历史项，两个历史项的筛选条件可以不同。`popstate` 使用原文档中保存的旧内容。`/away` 是另一份真实文档，可用浏览器后退返回。

`pageshow.persisted` 记录实际浏览器缓存恢复，不人为伪造。浏览器未启用前进后退缓存时，跨文档往返仍可观察，但返回会重新请求文档，不会被记成恢复展示。

供方控制只改模拟源，不自动更新已打开或已恢复的页面；恢复页面需要用户重新确认才会拿到新数据。

## 通用控制

`GET /api/snapshot` 查看当前原始源状态，可带 `probe` 查询参数作为一次取数的代号。`POST /api/action` 接收 JSON 对象 `{"action":"动作名"}`。可用动作：reset、publish。

控制只改变模拟源，不代表接收器已经处理了变化。

## 页面回报的事实

门户页面在用户本来就会触发的动作之后，通过采集绑定回报自己的状态：文档身份、文档序号、Navigation API 当前历史项的 `key`/`id`/`index`、`history.state` 中的设备与筛选、可见内容、取数依据和递增事件序号。

- 文档身份与文档序号放在 `sessionStorage` 中，跨文档往返后仍可辨认是否回到同一份文档。
- 历史项身份以 `navigation.currentEntry.key` 为准；同一 URL 的两个历史项 key 不同。
- 锚点变化会新增历史项但仍是同一文档，记录为 `hash` 变化。

页面自述只是线索：采集器必须亲眼看到对应的 `/api/snapshot` 响应，才把取数记为 `verified`。没有浏览器导航事实、事件序号倒退或页面现场已改变的上报会被归档为 `stale`/`late`。

## 来源证据

源端请求记录只用于核查服务行为；接收器自身的审计、状态和输出由 `src/collect.mjs` 与 `src/domain.mjs` 负责。源端重启会恢复默认资料，但本地接收文件不会自动清空。

所有资料均由本项目构造，包含的机构、设备、会话和文件仅供本地使用，不访问真实账号。浏览器操作应通过正常可见界面；测试用源控制接口不是业务采集捷径。
